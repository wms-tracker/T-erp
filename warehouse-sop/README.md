# Warehouse SOP Management System

ระบบบริหารจัดการเอกสาร SOP สำหรับคลังสินค้า ใช้งานผ่านเว็บเบราว์เซอร์ รองรับหลายผู้ใช้ หลายแผนก หลายระดับสิทธิ์ พร้อมกันแบบ Real-time

## เริ่มใช้งาน

ต้องมี **Node.js 22.13 ขึ้นไป** (ไม่ต้อง `npm install` — ไม่มี package ภายนอก)

1. ดับเบิลคลิก `START.bat` (หรือทางลัดบนเดสก์ท็อป) — โปรแกรมจะเริ่มทำงานและเปิดหน้าเว็บให้อัตโนมัติ
   ถ้าเปิดอยู่แล้ว กดซ้ำจะแค่เปิดหน้าเว็บ ไม่เปิดซ้อน · ย่อหน้าต่างดำไว้ได้ แต่อย่าปิด
2. หรือเปิด `http://localhost:5300` เองบนเครื่อง server
3. เครื่องอื่นในวง LAN/Wi-Fi เดียวกันเปิดตาม IP ที่หน้าจอ server แสดง เช่น `http://192.168.1.20:5300`
   (ครั้งแรก Windows อาจถามสิทธิ์ Firewall ให้กด "Allow")

### บัญชีเริ่มต้น (รหัสผ่าน `Sop@1234` — ระบบบังคับให้เปลี่ยนเมื่อเข้าครั้งแรก)

| ชื่อผู้ใช้ | บทบาท |
|---|---|
| `admin` | ผู้ดูแลระบบ — จัดการแผนก ผู้ใช้ ตั้งค่า |
| `manager` | Warehouse Operations Manager — อนุมัติ/ยกเลิก SOP ทุกแผนก |
| `ob.head`, `ib.head` | หัวหน้าแผนก — ตรวจสอบ SOP ของแผนกตน |
| `ob.staff` | ผู้จัดทำ — สร้าง/แก้ไข SOP ของแผนกตน |
| `viewer` | ผู้อ่าน — เห็นเฉพาะ SOP ที่ประกาศใช้แล้ว |

**หลังติดตั้งจริง:** เข้า `admin` → ตั้งค่าองค์กร (ชื่อบริษัท โลโก้) → สร้างผู้ใช้จริง → ปิดใช้งานบัญชีตัวอย่างที่ไม่ใช้

## ความสามารถ

- **Dashboard** — จำนวน SOP ทั้งหมด / ใช้งานอยู่ / ร่าง / รออนุมัติ / ส่งกลับแก้ไข / เลยหรือใกล้กำหนดทบทวน, กราฟแยกตามแผนก, กราฟ Workflow 12 เดือน, งานที่รอผู้ใช้, ประวัติล่าสุด, ตัวกรองแผนก สถานะ ช่วงเวลา
- **SOP Management** — สร้าง แก้ไข คัดลอก, ขั้นตอนไม่จำกัด (เพิ่ม/ลบ/แทรก/ลากจัดลำดับ), รูปประกอบทุกขั้นตอน, แนบ PDF/Word/Excel, กำหนดผู้รับผิดชอบ ผู้ตรวจสอบ ผู้อนุมัติ วันเริ่มใช้ วันทบทวน, ค้นหาด้วยรหัส ชื่อ แผนก และคำในเนื้อหา
- **Workflow** — Draft → Submitted → Department Review → Manager Approval → Published, ส่งกลับ (Revision Required) ต้องระบุเหตุผล, Obsolete
  - ผู้จัดทำ และผู้ที่ร่วมแก้ไขเนื้อหา ตรวจสอบ/อนุมัติฉบับนั้นไม่ได้
  - ผู้ตรวจต้องเป็นหัวหน้าแผนกนั้น (หรือผู้ที่ถูกกำหนด) ผู้อนุมัติต้องมีบทบาท Manager/Admin
  - บันทึกวัน เวลา ผู้ดำเนินการ และความคิดเห็นทุกครั้ง
  - ฉบับที่ยังไม่อนุมัติมีป้ายเตือน "ห้ามใช้ปฏิบัติงาน" ทั้งบนจอ Word และ PDF และผู้อ่านมองไม่เห็น
- **Revision History** — Rev.00, Rev.01, … เก็บเนื้อหาครบทุกฉบับ, ฉบับที่อนุมัติแล้วถูกล็อกห้ามแก้ไข, เปรียบเทียบความต่างระดับคำ (รองรับภาษาไทย), ดาวน์โหลดฉบับเก่า, บันทึกผลทบทวนและวันทบทวนครั้งถัดไปโดยไม่ต้องออก Rev. ใหม่
- **Export** — Word (.docx) รูปแบบมาตรฐานองค์กร (โลโก้ ชื่อบริษัท รหัสเอกสาร Rev วันที่มีผล ตารางลงนาม เลขหน้า X/Y ประวัติการแก้ไข), พิมพ์ / PDF (หัวกระดาษซ้ำทุกหน้า), ทะเบียน SOP เป็น Excel
- **หลายผู้ใช้พร้อมกัน** — ข้อมูลอัปเดตทันทีทุกหน้าจอ, แจ้งเตือนเมื่อมีงานเข้า, แสดงว่าใครกำลังเปิด/แก้ไขเอกสารเดียวกัน, ป้องกันการบันทึกทับกัน
- **แผนก** เพิ่ม แก้ไข ปิดใช้งาน ลบ ได้จากหน้า "จัดการแผนก" (ลบได้เมื่อไม่มี SOP/ผู้ใช้ผูกอยู่)

## ข้อมูลและการสำรอง

- ข้อมูลทั้งหมดอยู่ในโฟลเดอร์ `data/` (`sop.db` + `uploads/`) — **สำรองโฟลเดอร์นี้เป็นประจำ** (ควรปิด server ก่อนคัดลอก)
- เปลี่ยนที่เก็บข้อมูล/พอร์ตได้ด้วย environment variable: `SOP_DATA_DIR`, `PORT`, `HOST`

## โครงสร้าง

```
server/index.js   API, สิทธิ์, workflow, real-time (SSE)
server/db.js      SQLite schema + ข้อมูลตั้งต้น
server/docx.js    สร้างไฟล์ Word    server/xlsx.js  สร้างไฟล์ Excel    server/zip.js
public/           หน้าเว็บ (index.html, app.js, app.css, print.html, diff.js)
test/             node test/workflow.test.js — ทดสอบ workflow ทั้งหมดกับฐานข้อมูลชั่วคราว
```

## ข้อจำกัดที่ควรรู้

- ใช้ HTTP ภายในวง LAN — ถ้าจะเปิดใช้งานผ่านอินเทอร์เน็ต ควรวางหลัง reverse proxy ที่มี HTTPS
- ยังไม่มีระบบส่งอีเมลแจ้งเตือน (แจ้งเตือนในระบบเท่านั้น) และยังไม่เชื่อม Single Sign-On / Active Directory
- การ "เปรียบเทียบ" เทียบข้อความ; รูปภาพแสดงเป็นจำนวนรูปที่เปลี่ยน
